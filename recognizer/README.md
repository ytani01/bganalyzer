# 盤面認識プロトタイプ（ステップ1）

スマホで撮った実ボードの写真から、各ポイントの駒の数と色、バーの駒、上がった駒を読み取り、
GNU Backgammon にそのまま渡せる **Position ID** を出します。

## 使い方

```
uv run python board.py <写真> --corners x1,y1,x2,y2,x3,y3,x4,y4 --home left|right|auto [--bottom-colour 0|1] [--debug 出力先]
```

- `--corners`: 盤の遊戯面（左右のフィールド＋バー、枠の内側）の四隅。手前側プレイヤーから見て 左上, 右上, 右下, 左下 の順。
  ざっくりで構いません（盤の縁と三角形の先端で自動補正します）。アプリでは下の「四隅の推定」で初期値を置き、ユーザーがドラッグで直します。
- `--home`: 手前プレイヤーのホームボードが左右どちらか。`auto` なら駒の並びから推測する（下の「ホームボードの推測」）。
- `--bottom-colour`: 手前プレイヤーの駒の色（0 = 暗い方、1 = 明るい方）。アプリでは「自分の色」を選んでもらいます。
- 出力: 盤面のアスキー表示と JSON（points, bar, off, pips, position_id_white_on_roll / black_on_roll, errors）。
  White = 手前プレイヤー。駒が15個でないときは `errors` に出るので、アプリで手修正を促せます。

依存: Python 3, numpy, opencv-python-headless。

## 仕組み

1. 四隅 → 真上から見た盤への射影変換。
2. 盤の縁を直線で検出して補正し、さらに **三角形の先端と辺** に合わせて射影変換を推定し直す。
   三角形は盤面に印刷されているので、斜め撮影でも枠の高さによるズレを受けない。
3. 盤の地の色・三角形2色・枠の色を自動で学習。
4. 駒は円として検出し、「縁がはっきりした円」「中が単色」「そこが空いていた場合の色（地・三角形、縁の近くなら枠）と違う」で選別。
   山の途中や、2 個以上の山と枠の間にある弱い円（白い三角形の上の白い駒、茶色い三角形の上の茶色い駒など）も駒とみなす。
   駒の山に入った円だけで2色を学び（ダイスカップなどに色の片方を取られないように）、反射で白っぽく写った色付きの駒（赤がピンクに見える等）は色味で色付きの側に戻す。
5. 列の位置を、見つかった駒の並びに合わせて微調整する（三角形が見えにくい盤やアプリ画面向け）。
6. ポイントごとに、根元から連続して、まっすぐ積まれた駒を数える（途中の1〜2個の見落としは補う。アプリのように駒が重なった山は重なりの間隔で数える）。
   横にずれて重なった丸（ダイスカップ）は山とみなさない。1個だけの駒は、はっきりした円のときだけ数える。
   上がった駒 = 15 −（盤上＋バー）。

## ホームボードの推測（`home_prior.py`、TODO-013）

写真から分かるのは駒の並びだけで、ホームを左右逆にしても、同じ並びを鏡に映した合法な局面になる。
ただ実際の対局では駒の立ち方が左右対称ではない（6・8・13 ポイントに集まり、7 や 12 は少ない、
後ろに残る駒は 2〜3 個まで など）。そこで gnubg の自己対戦（0-ply、3 割は 2〜4 番目の手も指す。
4000 局・27 万局面）から、ポイントごとに「手前の駒が何個／奥の駒が何個」の出やすさを学んで
`home_prior.json` に入れ、両方の読み方の尤もらしさ（対数）を比べる。差が 1 未満なら決めずに既定（右）にする。

- 作り直し: `uv run python recognizer/home_prior.py`（gnubg が要る。数十秒）
- 自己対戦の別の 500 局（約 3.4 万局面）: 差が 1 以上になるのが 99.9%、そのうち 100% 当たる。
  24 ポイント中 8 か所を読み間違えた（駒の見落とし・1 個違い・色違い）ことにしても、98.8% で決めて 98.9% 当たる。
- サンプル（`evaluate.py` の home guess）: 23 枚すべて当たる。読み取りが 12/24 の dark-homeleft は差が 1.6 で、ぎりぎり決まる
  （leather-cups も 0.5.0 までは同じだったが、0.5.1 で 19/24 になり差が 19.5 に広がった。Raspberry Pi で測定）。
- commons-case-midgame は正解の方を直した（ホームは右ではなく左。右だと両方とも 24 ポイントに 3〜4 個残っていることになる）。
- 手前の駒の色を逆に選ぶと、180° 回した局面と区別がつかないので、左右も逆に推測する
  （アプリで「駒の色を入れ替える」を押したら「左右を入れ替える」も押す）。

## 四隅の推定（`corners.py`）

写真を読み込んだ直後に、アプリが四隅の初期値として出すための推定。`find_corners(img)` が
左上・右上・右下・左下（画像の画素）を返し、盤が見つからなければ `None`（アプリは画像の内側に余白をとった長方形から始める）。
コマンドラインでは `uv run python corners.py <写真>...`。

1. 長辺 800px に縮め、色を 8 つに分け、細長い三角形の形をした色の領域を盤の三角形とみなす。
2. 下向き（奥の列）と上向き（手前の列）に分け、先端と底辺がそれぞれ一直線に並ぶものを残す。
   底辺の直線が遊戯面の奥と手前の縁。駒で底の側が隠れた三角形も、先端と向きから使う。
3. 見つかった三角形を 12 ポイント（両フィールド 6 つずつ・間にバー）に当てはめる。外側のポイントは駒で
   隠れていることがあるので、何ポイント目から始まるかの候補をいくつか作る。
   三角形が見つからなかったポイントは駒に隠れているはずなので、先端のあたりが盤の地の色のままの候補は捨てる。
4. 候補ごとに左右の端の近くで、全長にわたって同じ向きの明暗がある直線（枠の内側の縁）を探す。
   枠の外の箱や物の縁の方が強いことが多いので、三角形に近い方を選び、外側はずっと強いときだけ選ぶ。

三角形の色が地とほぼ同じ盤（彫った盤の photo4）や、三角形のないアプリ画面（screen1）は見つからない。

当たり具合（アプリと同じく長辺 2048px に縮めた写真で、目視の四隅とのずれの最大。写真の長辺に対する割合）:

| データ | 四隅のずれ | 推定した四隅のままで読めたポイント（目視の四隅では） | 時間 |
|---|---|---|---|
| photo2 | 2.4% | 22（22） | 0.7 秒 |
| photo3 | 1.9% | 24（23） | 0.3 秒 |
| photo4 | 見つからない | － | 0.1 秒 |
| screen1 | 見つからない | － | 0.1 秒 |
| screen2 | 2.8% | 24（24） | 0.2 秒 |
| 合成画像 20枚 | 16 枚が 3.5% 以内、残りも 5.4% 以内 | － | 0.3 秒前後 |

元の大きさの写真や 1024px に縮めた写真では、photo2・photo3 で左右どちらかの端が 1 ポイント分（5〜8%）ずれることがある
（枠の内側の縁が淡く、外側の箱や駒の山の縁と取り違える）。テストは `analyzer/test_api.py` の `test_corners_*`。

## ダイス（`dice.py`、TODO-015）

`recognize()` の `info["dice"]` に、フィールドに転がっているダイスを入れる: `values`（読めた 2 つの目、大きい方から。
自信がないときは `null`）と `dice`（見つけたダイスごとの位置・大きさ・目・`sure`・`on_bar`）。アプリは `values` を
ダイスの目の初期値にする。

1. 盤を写真の解像度で真上から見た形に写し直す（駒の直径が 120px になるまで。ダイスの目は数画素しかない）。
2. 明るさのしきい値を 16〜248 まで 8 ずつ変え、明るい側・暗い側それぞれで、駒の直径の 0.28〜1.1 倍の大きさの
   正方形（四隅があって外接長方形をほぼ埋める。駒の円は埋めない）を体として集める。
3. 体の中で、まわりの面より暗い（明るい）小さな丸を目とする。面との差の取り方を 6 通り（局所的な差・明るさの段階 ×
   切る位置 3 つ）試し、目の並びが体の向きにそろったダイスの面（1〜6）になっているものを「読み」とする。
   暗い目と明るい目の両方で読めた体は捨てる。駒の真ん中のくぼみは 1、彫った模様は小さなダイスに見えることがあるので、駒の上のものは捨てる。
4. 同じダイスはしきい値を変えても何度も見つかる。場所ごとに読みを集め、4 回以上読めて 75% 以上が同じ目なら確か（`sure`）とする。
   偶然の模様は 1〜3 回しか読めない。
5. バーの上を除いて、確かなダイスがちょうど 2 つで、目の色（明暗）・大きさ・色が揃っているときだけ `values` を出す。
   1 つだけ（もう 1 つがカップの中など）、3 つ以上（2 人分のダイスが盤に出ている）は `null`。

`samples/*.truth.json` の `dice` が正解（読めるはずの 2 つの目、なければ `null`）。`evaluate.py` が `dice ok / not read / WRONG` を出す。

## キューブ（`cube.py`、TODO-025）

`recognize()` の `info["cube"]` に、ダブリングキューブの場所を入れる: `at`（`"centre"` = 盤の真ん中の高さで誰も持っていない、
`"white"` = 手前の側、`"black"` = 奥の側）と位置・大きさ。見つからないときは `null`。**数字は読まない**
（アプリは片側にあるときの数を 2 とし、違えば手で直してもらう）。

1. 遊戯面の左右に駒 2.2 個分ずつ広げて、真上から見た形に写し直す（キューブは枠やトレイに置かれることが多い）。写真の外は使わない。
2. `dice.py` と同じやり方で、駒の直径の 0.45〜1.15 倍の正方形を集める。
3. 駒の上のもの（キューブより大きな円の中）、`dice.py` が確かと見たダイス、目の並びがダイスの面になるものは捨てる。
4. 面に数字らしい印（まわりより暗いか明るい、1〜8 個のかたまりで、面の 4〜40%）があるものを残す（0.6.1 までは 4 個。Pi では photo3 の「64」が 5〜7 個に割れて見つからなかった）。
5. しきい値を変えて 4 回以上見つかり、ほかの候補の 2 倍以上見つかる場所があるときだけ答える（0.6.0 までは 6 回。JPEG で保存し直した photo3 が見つからなかった）。上下の真ん中から盤の高さの 18% 以内なら `centre`。

## 撮影の傾きの警告

`recognize()` の `info` に `tilt_deg`（タップした四隅から推定した、真上からの傾き。0° が真上）と
`warnings`（40° を超えると `["oblique"]`）を入れている。サンプルでは真上から撮った写真が 12〜23°、
スクショが 0°、斜めの photo1（削除済み）が 69°。アプリはこれを見て撮り直しを勧める。

## 盤の位置（geometry）

`info["geometry"]` に、最後に合わせた盤の位置を入れている: 遊戯面の四隅（画像の画素）、12 列の中心と
バーの両端（遊戯面の幅に対する割合）。アプリは元の写真を盤面図にそろえて表示するのに使う。認識の結果は変わらない。

## 撮影ガイド（アプリで表示する想定）

- 盤の **真上から**、盤全体が画面いっぱいに入るように撮る。
- 影や照明の反射が強い所を避ける。

## 位置ごとに判定する読み方の試作（`slots.py`、TODO-032）

円を探す代わりに、射影変換の後に n 個目の駒が来る位置（根元から (n−0.5)×直径）ごとに「空き・暗い色・明るい色」を判定し、
「1 ポイントは 1 色で、根元から続けて積む」として各ポイントの (色, 数) を一度に決める。空いた位置と駒の見た目は、
円で読んだ結果から写真ごとに学ぶ（三角形の色と何番目かごとに、空いたと読んだ位置の色の中央値）。
`board.recognize(..., method="slots")`、`evaluate.py --slots` で動く。アプリは今までどおり円で読む。

2026-10-14、x86_64 で全 23 枚（552 ポイント）: **円 495、位置ごと 478**。

- 重みは総当たりで決めた（`SLOTS_TUNE=縁の重み,しきい値`）。円の縁の強さは空いた三角形の根元でも 0.4〜0.5 あり、
  重くするほど悪い（縁 1.0 で 403〜452、0.1 で 478、0 で 477）。色だけでほぼ決まる。
- 円より良い: commons-nardy-midgame 18 → 19、commons-travel-case 21 → 22。同じ: 15 枚。
- 円より悪い: commons-set-cube-dice 12 → 3（円の読みが悪く、そこから学んだ見た目が外れる）、photo4 24 → 22、
  leather-cups 20 → 17 など。5 個の山を 4 個と読むことがある。
- 円の読みから学ぶので、円が大きく外れる写真では一緒に外れる。円が出ない駒（commons-dark-homeleft、TODO-027）は
  12 のままで、円の代わりにはならなかった。
- ai1 の盤（えんじ色の駒と赤い三角形）の写真がサンプルにないので、いちばん効くと考えた場面は確かめていない（TODO-030 で写真が集まったら測る）。
