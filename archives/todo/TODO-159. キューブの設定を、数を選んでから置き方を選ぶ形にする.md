## きっかけ

キューブの設定（`#sheet-cube`）が、「中央・白・黒」のボタン、キューブの数の select、「ダブルされたところ」のチェックに分かれていて分かりにくかった（2026-10-19 ユーザーが決めた）。

## やったこと

PR #473、analyzer 0.89.0。設定を、数を選んでから置き方を選ぶ形にした。

- 「中央・2・4・8・16・32・64」を 1 列のボタンにした（`cubeValue`）。数を押すと、その下に 2 行の選択肢が出る。中央のときは出ない
  - 「白側に置く」「黒側に置く」（`cubeHold`）: その人が持っている（`offered: false`）
  - 「白に対してダブル」「黒に対してダブル」（`cubeDouble`）: その人がテイクかパスかを決めるところ（`offered: true`）
- 中央から数を押したときの既定（レビューのあと、ユーザーが決めた）: 置く側は次に振る人（`onRoll`）の相手側（写真から読むときの `fromRead` と同じ）。ダイスが入っていなければ「…に対してダブル」、入っていれば「…側に置く」。次に振る人も入れた目も変わらない
- `analyzer/static/cube.js` に `buttons`（cube から、各行で押されて見えるボタン）と `numberPatch`（数の列を押したときの cube の変更）を足した。`app.js` の `SEGMENTS` は `setCube` を通すので、クロフォード（TODO-153）の扱いはそのまま
- 数のボタン（中央以外）ではシートを閉じない（`choseInSheet` の例外）。置き方か中央を選ぶとシートが閉じる
- `analyzer/README.md`・`docs/raspi.md` の旧 UI の言い方を直し、`tools/ui_snapshot.py` の旧 id を新しい seg 名に直した。`test_pwa.py` に `test_cube_settings_buttons` を足した

## 分担の振り返り

- **見つけたこと:** implementer は、自分で画面を動かして、数を押すとシートが閉じること（`choseInSheet`）と「中央」が 2 行に折れることを見つけて直した。reviewer は、中央から数を押したときの既定が「白に対してダブル」に固定で、次に振る人を黙って逆にすること（ダイスが入っていても `offered: true` でダイスが使われなくなること）、README:93 の旧 UI の言い方の漏れ、`app.js` の seg の表示の入れ替えをテストが守れていないこと、`docs/raspi.md` の言い方を見つけた。verifier は、仕様どおりに動くことを確かめ、閉じ方と次に振る人の変わり方を気づきとして挙げた
- **見込みと食い違った理由:** 見込みは 1 巡で、reviewer の指摘で 1 巡直しが入った。既定の置き方は、implementer が「旧 UI と同じ」としていたが、旧 UI は前の値を引き継いでいた（実際は同じではなかった）。依頼に既定の置き方を書いていなかった
- **次に同じ規模なら:** 選択肢の既定を決める項目では、依頼の最初に、既定の置き方（次に振る人・ダイスとの関係）を書く。旧 UI を直す項目では、旧い言い方が残る文書を `rg` で洗い出させる（README と docs の両方）。テストは、表示の写し方（どの行に何が押されて見えるか）を、実際のコードを呼んで確かめる形を最初から求める
