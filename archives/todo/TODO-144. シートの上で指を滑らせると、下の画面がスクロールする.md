## きっかけ

2026-10-19 ユーザーの報告。ダイスのシートを開いて指を滑らせると、下の画面がスクロールする。シート（`.sheet`）は画面に固定してあり、中にスクロールするものが無いので、指の動きが下の画面に伝わっていた。ゲーム・キューブのシートも同じ。
シートの上だけスクロールを止め、シートの外では今までどおりスクロールできるようにする（同日ユーザーが決めた）。

## やったこと

- `analyzer/static/style.css` の `.sheet` に `touch-action: pinch-zoom` を足した。最初は `none` にしたが、レビューで、シートの上で始めたピンチのズームまで止まると指摘されたので `pinch-zoom` に替えた
- analyzer を 0.79.1 に上げた（#425）

## 確かめたこと

- verifier: タッチを使えるモバイル表示の Chromium で、`Input.dispatchTouchEvent` を使って指を滑らせた。シートの上では scrollY が 400 → 400 のまま、シートの外では 400 → 652。比べるために同じページのシートを `touch-action: auto` にすると 400 → 652 になり、この測り方で直す前と後の違いが出ることを確かめた。ダイスの目のボタンもタップで効いた
- ユーザーがスマホで確かめた（2026-10-19）

## 分担の振り返り

- reviewer: ピンチのズームまで止まる点を見つけ、`pinch-zoom` に替えた。ボタン・プルダウン・チェックボックスのタップが届くことも確かめた。スワイプは CDP の `synthesizeScrollGesture` で送ったが、シートの外でもページが動かず、比べられなかった
- verifier: `synthesizeScrollGesture` では動かず、`dispatchTouchEvent` で測った。依頼では、ポート 8000 の常駐サービスを直す前の対照にするつもりだったが、常駐サービスはこの作業ツリーを読んでいて、直したあとの CSS を配っていた。そこで、同じページで `touch-action` を戻す方法に替えて比べた
- 見込みどおりの編成で済んだ。食い違ったのは、対照にするつもりだったものが使えなかったことだけ
- 次に CSS を 1 行変えるだけの項目でも、同じ組み方にする。ただし、指の動きを測る依頼には、初めから `dispatchTouchEvent` を指定する。直す前との比べ方は「同じページで直した規則を外す」にする（常駐サービスはこの作業ツリーを読んでいて、比べる相手にならない）
