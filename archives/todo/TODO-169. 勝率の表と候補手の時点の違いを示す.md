## きっかけ

解析結果に、勝率の表（振る前の局面の評価。36 通りの目の平均）と候補手の値（その目で動かした後の評価）が並ぶ。
悪い目のとき候補手の値は勝率の表より低くなり、1 ポイントマッチで「MWC と勝率が違う」と受け取られた。
調べると計算は正しく、どちらも同じ深さ・キューブレス・手番から見た値で、時点が違うだけだった。

## やったこと

- 利用者と決めて、見出しを付けることにした: 勝率の表の上に「ダイスを振る前」、候補手の一覧の上に「この目で動かした後」
- `analyzer/static/result.js` で、候補手の一覧（`<ol class="moves">`）の前と勝率の表の前に `<h3>` を足した。
  動かせる手が無いとき・ダイスが無いときは前者を出さない。勝率の表の見出しは終局以外で常に出す
- 結果の画面に小見出しの class が無かったので、`analyzer/static/style.css` に `.result h3` を足した
- `analyzer/test_pwa.py` に `test_result_headings_say_when_the_numbers_are_for` を足した
- analyzer 0.92.0 → 0.92.1（`analyzer/app.py`・`analyzer/static/app.js`）。`analyzer/README.md` の結果の画面の説明に追記した
- 勝率・候補手の数値と計算（`engine.py`・`analysis.py`）は変えていない

## 分担の振り返り

- **見つけたこと:** 見た目のデザインの良し悪しは評価に含めず、見出しの位置と重なりだけを測らせた。見つかった食い違いはなかった。
  キューブの判断だけの局面（ダイスなし）でも「ダイスを振る前」が出ることは、指示どおりの動きとして verifier が報告した
- **見込みと食い違った理由:** 見込みどおりに implementer と verifier で足りた。main の記録に Opus 5.5 が混ざったのは、利用者との相談が Opus 5.5 だったため
- **次に同じ規模ならどう組むか:** 文言と見出しだけの変更は同じ組で足りる。見出しの class が結果の画面に無いとき、小見出しの置き場を先に決めておくと CSS の足しを実装の依頼に書ける
