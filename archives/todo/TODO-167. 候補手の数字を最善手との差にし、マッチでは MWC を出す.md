## きっかけ

TODO-166 と同じ表記の点検から。候補手のエクイティは各手の絶対値だけで、符号は負のときだけ付いた。gnubg・XG は 2 位以下を最善手との差で、
符号を常に付けて出す。マッチでも単位はエクイティ（実は EMG）で、gnubg・XG が既定で出す MWC が出なかった。キューブレスとキューブフルが
同じ「エクイティ」の語で並んでいた。方針（2026-10-20 ユーザーが決めた）は、初心者に分かりやすい表記を優先し、定着した言い方からかけ離れたものだけ直す。

## やったこと

- 実装の前に、gnubg の Python 拡張の `gnubg.eq_to_mwc(エクイティ, cube_info)` で MWC が取れることを実測した。キューブの判断の値は、gnubg の hint を
  `set output mwc on` で出した値と 0.01% 以内で一致した
- `analyzer/engine.py`: マッチでは候補手とキューブの判断に `mwc` を付け、キューブレスの MWC も返す。キューブの判断はダブル前のキューブの `cube_info` で変換する
- `analyzer/analysis.py`: 結果に `mwc`（%、小数 2 桁。マネーは `null`）、候補手とキューブの判断にも `mwc`。マッチでダブルされた局面は、gnubg に渡すキューブを
  ダブルした後の値にした（勝率の表の MWC・EMG を今のキューブで数える。レビューの指摘でユーザーが決めた）
- `analyzer/static/result.js`: 候補手の 1 位は値、2 位以下は 1 位との差で、符号を常に付ける（マッチは MWC %）。勝率の表は「キューブレス エクイティ」
  （マッチは「キューブレス MWC」と「キューブレス EMG」）、キューブの表は「キューブフル エクイティ」（「キューブフル MWC」）。注記は「最善手と勝率はキューブなし」
  （候補手の語には付けない。ユーザーが決めた）
- `analyzer/README.md`: API の `mwc` と結果の画面の説明
- テスト: `analyzer/test_api.py` に 2 つ（MWC の向き、キューブ 2 以上、ダブルされた局面）、`analyzer/test_pwa.py` に 1 つ（差・符号・語）
- analyzer 0.90.1 → 0.91.0（`APP_VERSION` も）。PR #495
