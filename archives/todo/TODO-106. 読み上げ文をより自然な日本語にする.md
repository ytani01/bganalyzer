## きっかけ

ユーザーが、結果の画面の読み上げ文をより自然な日本語にすると決めた（2026-10-17）。

## やったこと

- 今の文を 15 の場合ごとに並べ（`archives/agents/TODO-106/speech_samples.js`）、全部を見直した修正案をユーザーに出した。ユーザーの直しは「ダブルしてもしなくてもよいことは読まない」の 1 つ
- `analyzer/static/result.js` の `speechText`・`standingToSpeech`・`moveToSpeech`:
  - 読み上げでは「白の人」でなく「白」（画面の文は変えない）
  - ダイスがあるとき「白の 6 5 は、とても良い目です。最善手は、…です。」（ふつうの目は「白の 6 5 の最善手は、…です。」）。運の良し悪しを最善手より先に言う。動かせないときも同じ順
  - ダイスが無いとき「次は白の番です。」。キューブの判断を読むときは、その文に誰のことかが入るので言わない
  - キューブ: 「白はダブルすべきで、黒はテイクです。」「白のリダブルに、黒はテイクです。」「白はまだダブルしない方がよいです。」、ギャモン狙いを「白はダブルせず、ギャモンを狙う方がよいです。」（前は「まだダブルしません」と読み違えていた）。してもしなくてもよいときは読まない
  - 終局は「白の勝ちで、ゲームは終わっています。」だけ（前は誰が振るかも読んでいた）
  - 「ほぼ勝ちです」「ギャモン勝ちの見込みも十分あります」「ピップ数では白が大きくリードしています」、手は「13から8へ2枚」
- `analyzer/README.md` の読み上げの説明、`tools/pi_ui_check.py` の `check_speech` と `docs/raspi.md`（「ピップ」の語ではなくピップの数を読まないことを見る）
- analyzer 0.62.1 → 0.62.2（`APP_VERSION` も）

## 確かめたこと

- reviewer: README の説明が古い順のまま、`pi_ui_check` の正規表現が新しい文の「ピップ数では」に当たる、動かせないときだけ運の良し悪しが後に来る、4 つの文がテストで守られていない、を見つけた。すべて直した（`archives/agents/TODO-106/reviewer-report.md`）
- verifier: 15 の場合の文が文案と一字一句一致、読み上げのテストが通る、2 か所を壊すとテストが落ちる（`archives/agents/TODO-106/verifier-report.md`）
- PR #318 の GitHub Actions の `test` が通った
- ローカル: マージ後の analyzer 0.62.2 以降で、写真を読み取って解析し「読み上げ」を押すと「白の 4 2 の最善手は、8から4、6から4です。ほぼ互角です。」が読まれた

## 分担の振り返り

- reviewer は文書・確認の道具・テストの抜けを見つけた。文案の並べ方では拾えない所（README、pi_ui_check）で、入れてよかった
- verifier は食い違いを見つけなかった。文案との一字一句の照合と、壊すと落ちることの確認で足りた
- 見込みでは reviewer を「分岐が変わるなら」としていたが、キューブの分岐が変わったので入れた。次に文言の項目を立てるときは、文言だけか分岐も変わるかを、文案を出した時点で決める
