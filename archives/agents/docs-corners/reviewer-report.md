## 食い違い・検討

1. 検討 / 長辺 5% の基準（doc L73 と corners.py:315）
   - 文書: 「写真の長辺の 5%」
   - コード: `NEAR * max(h, w)` の h, w は縮めた切り出し範囲 (`small`)。README(L246): 「crop が無ければ写真全体」の長辺
   - 範囲を囲んだときは範囲の長辺。文書は README より不正確。「探す範囲（囲んだときはその範囲）の長辺」が正確

2. 検討 / 「ほとんど」と 45%（doc L64 と corners.py:40,154）
   - 文書 L64: 「帯の行のほとんどに縁が続いているか」。L120: 「45% に縁が続かないと」
   - コード: 閾値は 45%（半分未満）で、連続は要求しない（行ごとに縁の画素が 1 つでもあれば数える。3 画素に膨らませている）。docstring は "(almost) every row" だが閾値は 0.45
   - 「ほとんど」は 45% と合わない。「続く」も、連続ではなく行の割合

3. 検討 / 「左から順に最大 8 本」（doc L61）
   - コード(L152-158): 帯への覆い率の高い順に最大 8 本を選び、そのあと左から並べ替える。左から 8 本ではない
   - 図の文言が誤読を招く（「覆い率の高い順に 8 本、並びは左から」）

4. 検討 / 25% と 40% の対象（doc L58, L72）
   - 図 L58 は「間が写真の高さの 25%」だけ。範囲を囲んだときは 40%（TRIMMED[1]）になる（corners.py:305, least[1]）
   - 本文 L72 は幅の 50% と高さの 40% を書いているが、高さの判定が四角形でなく「奥と手前の候補の組」で行われる（x=w/2 での間隔）ことは、図と L72 で別々に書かれていて対応が分かりにくい。実害は小さい

5. 検討 / 「全部置いたらその四隅を返す」の前後（doc L22-23 の図と corners.py:370-387）
   - 図: 全部置いたかの判定が先頭
   - コード: 切り出しが 16 px 未満なら、全部置いていても None（L370）。また返す値は `snap(q, 0.1)` で 0.1 に丸められる
   - 実害は未確認（囲む範囲が 16 px 未満は通常の操作では起きにくい）

6. 好みの範囲 / 「四隅のあと」の説明（doc L127）
   - 「三角形の並びに合わせて…合わせ直す」だけだが、board.py:102-114 では先に枠の線で 2 回（refine）、三角形で 2 回（refine_tips）。固定時は列の位置（fit_columns）だけは合わせる（README L521-524）。「渡した四隅のまま読む」と書いてよいが、列は合わせる

7. 好みの範囲 / 「整数で」（doc L113）
   - 構造の点数（相関）は numpy の float64 で、exact.py を通らない。README も同じ書き方なので README と食い違いはない。文書の「縮小も勾配もハフ変換も整数」は正確（点数は含めていない）
