### 浮動小数点が混ざる所・あふれ（見てほしいこと 1）

最大値は、画素数 ≤ 800 × 800 = 640,000、座標の最大 255 × 80 = 20,400（L は 255 × 48 = 12,240）で見積もった。

| 箇所 | 型 | 最大 | 判定 |
|---|---|---|---|
| `key`（corners.py:97、int32 の `@`） | int32 | < 2^24 | 整数の matmul は BLAS を通らない。正確 |
| `(x - cj) ** 2` の 1 成分 | int32 | 20,400² ≈ 4.2e8 | int32 に収まる |
| `.sum(1)`（距離の 2 乗） | int64（numpy の既定） | 12,240² + 2 × 20,400² ≈ 9.8e8 | 収まる。コメントの `3 * (255*5*16)**2 < 2**31` も正しい（1.25e9） |
| `d * cnt`、`cumsum`（k-means++） | int64 | 9.8e8 × 640,000 ≈ 6.3e14 | int64 に収まる |
| `np.bincount(lbl, cnt)`（:77） | float64 | 640,000 | 2^53 未満の整数の足し算はどの順でも正確。int64 に戻しても変わらない |
| `np.bincount(lbl, x[:, i] * cnt)`（:78） | float64 | 20,400 × 640,000 ≈ 1.3e10 | 同上。途中の和もすべて 2^53 未満の整数 |
| `cost`（:84） | int64 | ≈ 6.3e14 | 収まる |

- `np.unique(return_inverse=True)` は argsort の並べ方（SIMD の種類で同じ値の順が変わりうる）に依らず、逆引きはキーの値だけで
  決まる。`argmin` は同じ値なら最初の添字。`rng.integers` は整数だけで乱数を作る。
- numpy の `Generator.integers` の乱数列は numpy の版をまたいで同じとは限らない（NEP 19）。uv.lock で版が固定されているので
  今は問題ないが、numpy を上げると四隅が変わり、新しいテストが落ちる（それで気付けるので害ではない）。

### CPU の差が残りうる所（実害は未確認、報告だけ）

- **前:** `cv2.resize(INTER_AREA)`（corners.py:505）は縮小率が整数でないとき float で足し合わせて 8 ビットに丸める。
  FMA の有無などで 1 画素でも 1 違えば、色の集合が変わり k-means の結果が大きく変わりうる。GaussianBlur の 8 ビットと
  BGR2Lab の 8 ビットは OpenCV が固定小数点で bit-exact にしている（はず。未確認）。テストの 3 枚はすべて縮小を通るので、
  CI で落ちればここが疑わしい。
- **後:** `minEnclosingTriangle`（double）、LSD（double と三角関数）、`np.arccos`（:149）、`np.exp`（:287。x86_64 の
  AVX-512 では numpy が別の実装を使う）、`np.polyfit`（LAPACK、OpenBLAS の CPU ごとのカーネル）。最下位ビットの差が
  閾値や同点の選択にかかったときだけ結果が変わる。
- **Sobel の後の勾配（:430-431）** は float32 だが、値が整数で 3 成分の 2 乗和 < 2^24、sqrt は正しく丸められるので CPU に依らない。
- 認識（board.py:558, 897）にはまだ `cv2.kmeans` が残っている。この項目の範囲（四隅）の外で、ポイントの読み取りは
  CPU で変わりうる（README の 495 対 492 の差）。

### k-means の実装（見てほしいこと 2）

- 重み付きの k-means++: 1 つ目は画素数、2 つ目以降は「最も近い中心との距離の 2 乗 × 画素数」に比例して選んでいる。正しい。
  `searchsorted(side="right")` で重み 0 の色（既に中心の色）は選ばれない。
- `cs[-1] == 0`: 色の種類が k より少ないときに起きる。`x[0]` を返して中心が重なるが、`argmin` が先の方を選ぶので後の方は
  空のクラスタになり、空のクラスタは前の中心を保つ（:79 の `np.where`）。壊れない。1 つ目の `pick(cnt)` では起きない（画素数 > 0）。
- 打ち切り: 中心が変わらなくなるか 20 回。重心を切り捨て（`//`）にしているので、まれに 2 つの状態を行き来しうるが、
  20 回で止まり、最後の中心で付け直したラベルと `cost` を使うので食い違いは無い。
- 2 回の試行のうち `cost` の小さい方。同じなら 1 回目（決定的）。

### テストの丸め（見てほしいこと 3）

違っていた: tavli-red-brown 11.3% 対 8.9%）。
