## 分かったこと（hedmzy、縮小後の座標。`k` は 1/200 の傾き、`c` は x=0 での y）

- 正解の上の辺は `(-0.8, 49.6)`。`_h_lines` の最強の線 `(-2, 57)` と**傾きがほぼ同じで 7px しか離れていない**。
  傾きの違う辺が吸われているのではなく、同じ傾きで近い線が `LINE_SEP`（12px）に吸われている。
  だから案 A の「傾きごとに抑制」は傾きの差を 10〜0 の間で変えても、正解の辺（`(-1,50)` 付近）は候補に入らない。
- `_swap` の前の上の辺は `(-2, 25)`（盤の外。`_inner` 0.0）。`out` の規則が移した先は `(-6, 70)`（`_inner` 0.833、点数 1.3112）。
  傾きの差は 4（0.02）で、正解の辺との差も小さい。案 B は差の上限を 4 以上にすると何も変えず、2 にすると別の線に移って悪化する。
- 移せたはずの `(-2, 57)` は `_inner` 0.625 < `INNER_IN` 0.75 で落ち、`(-6, 70)` が点数順で先に通った。
  `(-2, 57)` に置くと点数 1.2968、上の辺の端は y=146/126（正解 127/119。`(-6,70)` は 178/119）。
- 正解の四隅は点数 1.2800、`_inner` 上 0.292 で、検出（1.2770）とほぼ同点。点数だけでは区別が付かない。
- **実害は小さい**: 正解の四隅を渡しても検出の四隅を渡しても hedmzy は 1 点誤りで同じ。直す動機は四隅の見た目（ずれ 51px → 19px）。

## 案

- **案 A**（`plan-a.patch`、`_h_lines` で、抑制する範囲を傾きが `H_SLOPE_SEP` 以内の線だけに）: 差分は +7 −1。hedmzy は直らず、DK によって
  良くなる写真（champions の四隅）と悪くなる写真（galaxy-1・green-far の四隅）が混ざる。**筋は悪い**（原因が傾きの違いではなかった）。
- **案 B**（`_swap` の `for line in ...` の頭に `if i % 2 == 0 and abs(line[0] - sides[i][0]) > SWAP_SLOPE: continue`）: 差分は +4。パッチは残していない。
  上限 4〜6 は main と同じ結果、2 は悪化。**効かない**。
- **案 C**（`plan-c.patch`。別案）: `_swap` の「盤の外を走る上下の辺を内側へ移す」（`out`）ときだけ、
  ①点数順ではなく**今の線に一番近い線から**試し、②`INNER_IN` を 0.75 → 0.6 にする。差分は +9 −3。
  hedmzy のずれ 51px → 19px、iou 0.9795 → 0.9875。ほかの 3 枚は main と同じ。
  `INNER_IN` だけ 0.6 にしても（近い順なし）、近い順だけでも（0.75）変わらず、**両方が要る**。
  （`plan-c.patch` は、試すときに環境変数で切り替えていた `IN`・`NEAREST` を 0.6・True に固定して書き出したもの。`git apply` で当てられる）
