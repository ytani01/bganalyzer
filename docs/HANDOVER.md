# Claude のプロジェクトへの引き継ぎ

このリポジトリの作業を、別のアカウントの **Claude のプロジェクト**（claude.ai の Projects）で続けるための手順です。
Claude のプロジェクトそのものは別アカウントへ移せないので、相手側で新しいプロジェクトを作り、
このリポジトリをつないで、下の文面を貼れば同じ状態から再開できます（2026-10-12 時点の内容）。

リポジトリに入っている情報（[README.md](../README.md)、[CLAUDE.md](../CLAUDE.md)、[TODO.md](../TODO.md)、
各フォルダの README）は Claude が自分で読むので、ここには **プロジェクト側にしかなかった情報** だけを書いています。

## 1. GitHub 側の準備（今の持ち主がやる）

- 一緒に作業する: ytani01/bganalyzer の Settings → Collaborators で相手を招待する。
- 完全に渡す: Settings → General → Transfer ownership。リポジトリ名が `<新しい持ち主>/bganalyzer` に変わる。

## 2. 新しいプロジェクトを作る（引き継ぐ人がやる）

1. claude.ai で新しいプロジェクトを作る。名前と説明の例:
   - 名前: `BACKGAMMONボード分析`
   - 説明: `バックギャモンボードの写真を読み込み盤面を分析し、どちらが有利か判定する`
2. GitHub アカウントを Claude につなぐ（https://claude.ai/connect-github ）。
   リポジトリに Claude の GitHub App が入っていなければ、案内に従って入れる。
3. プロジェクトの設定でリポジトリ `<持ち主>/bganalyzer` を追加する。
4. 「3. プロジェクト指示」の文面をプロジェクトの指示（instructions）に貼る。
5. プロジェクトのチャットに「4. 最初のメッセージ」を送り、メモ（MEMORY）を作ってもらう。

## 3. プロジェクト指示（そのまま貼る）

`<持ち主>` は実際の GitHub アカウント名に置き換える。

```text
- ユーザーとのやりとりは日本語で行う。
- リポジトリ <持ち主>/bganalyzer で作業する前に main を pull し、リポジトリ直下の CLAUDE.md に従う。
- 自動マージ: スレッドが作った PR は、最新 main を取り込んでテストがすべて通り、差分を見直して
  問題がなければ、ユーザーの確認を待たずにそのスレッド自身がマージする。マージしたことは一言報告する。
  テスト失敗・未検証の重要事項・判断が必要な点がある場合はマージせず報告する。
- GitHub に CI はない。「テストが通る」は Claude の環境で `uv run pytest analyzer` が通ること。
```

## 4. 最初のメッセージ（プロジェクトのチャットに送る）

このメッセージで、前のプロジェクトのメモを新しいプロジェクトのメモに入れてもらいます。

````text
このプロジェクトは別アカウントから引き継いだものです。リポジトリの docs/HANDOVER.md を読み、
「5. プロジェクトのメモ」の各項目をプロジェクトのメモ（MEMORY）に保存してください。
そのあと、次にやることを TODO.md と HANDOVER.md から整理して教えてください。
````

## 5. プロジェクトのメモ（MEMORY に入れる内容）

前のプロジェクトのメモの中身です。リポジトリから読み取れることは省いています。

- **ユーザー:** やりとりは日本語。細かい技術判断は Claude に任せる方針（gnubg をサーバー側で動かすのも Claude が決めた）。
- **目標:** スマホで撮った実物の盤の写真 → 盤面認識 → GNU Backgammon で解析（勝率・ギャモン率・ピップ数）→ PWA で表示。
- **計画と進み具合:** 1 盤面認識（済）、2 gnubg 解析・サーバー側（済）、3 手動修正付きの PWA（済）、
  4 実写真での調整（**進行中**）。PR #1〜#8 はすべてマージ済み。
- **認識精度（24ポイント中）:** photo2 23、photo3 24、photo4 24、スクショ2枚 24、photo1（斜め撮影）14。
  PWA は長辺 2560px を超える写真を 2048px に縮めて送るので、photo3 → 23、photo4 → 22 に落ちる。ステップ4で見直す。
- **ユーザーの盤:** クラフト紙色の盤面、赤と紺の三角形、白い枠。駒はえんじ色と紫。えんじ色の駒と赤い三角形は
  色がほぼ同じ（Lab で差 ~8）で、色だけでは区別できない。斜めの写真が一番の弱点なので、真上から撮ってもらう。
- **公開先は未定**（TODO-002）。ホーム画面への追加には HTTPS が必要。サーバーレス関数は不可、ワーカー1つで常駐。
  どこに置くかはユーザーが決める。
- **Docker:** 必須ではなくサーバー公開用。`docker build` はユーザーの手元でまだ確認していない。
  Claude のクラウド環境からは Docker Hub（429）や ghcr（403）、deb.debian.org に届かず試せない。
- **公開前の注意（対応済み）:** `samples/` の photo1 には人の顔、screen2 には第三者のツイートが写っていたので、
  photo1 は顔をぼかし、screen2 はゲーム盤の画像以外を塗りつぶした（2026-10-13）。ただし Git の履歴には
  加工前の画像が残っている（TODO-003）。
- **ファイル:** プロジェクト共有フォルダの `backgammon/` に recognizer と samples の写しとデバッグ画像（`out/`）が
  あったが、正本はリポジトリ。新しいプロジェクトでは不要（必要なら `uv run python recognizer/evaluate.py` で作り直す）。
- **共有:** プロジェクトは非公開で、他のアカウントは追加できない。共同作業は GitHub の Collaborators で行う。

## 6. スレッドでの進め方

- 依頼はプロジェクトのチャットに書く。Claude が作業ごとにスレッドを立て、そのスレッドで進める。
  続きの指示や質問は、そのスレッドに書く。
- コードを変えるスレッドは、main を pull → ブランチで変更 → `uv run pytest analyzer` → PR → 自動マージ、の順に進める。
- 認識を変えたら `recognizer/evaluate.py` で精度を測り、`recognizer/README.md` の表を更新する（CLAUDE.md のとおり）。
- 新しい作業や決まったことは `TODO.md` に書く（番号は TODO-003 から）。
- 方針の変更や、次のスレッドが知っておくべきことは、プロジェクトのメモにも残してもらう。
